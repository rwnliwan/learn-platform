# METODE — Misi Serving: Latensi yang Membunuh Pengalaman (misi-gabung-serving-llm)

- **Sumber data:** SINTETIS — dibuat dengan generator acak (Python/numpy `default_rng(42)`, seed 42). BUKAN log produksi siapa pun, BUKAN data pengguna asli, TANPA kredensial, TANPA prompt/teks pengguna asli. Dinyatakan SINTETIS di briefing misi, di data room, di prosa lab, dan di sini.
- **File:** `request_logs.csv` — 240 baris (120 per varian), 12 kolom: `request_id, variant, prompt_tokens, completion_tokens, cache_hit, prefill_ms, queue_ms, ttft_ms, tpot_ms, decode_ms, total_ms, quality_score`.
- **Skenario yang dimodelkan:** dua varian serving chatbot LLM. Varian A = model FP16 penuh + KV-cache aktif (hit ~85%). Varian B = model terkuantisasi INT8 + KV-cache MATI diam-diam (hit 0% — ini disengaja sebagai bahan temuan lab & audit, bukan bug generator).
- **Distribusi generator (seed 42):** `prompt_tokens` ~ Normal(450, 200) clip 60–1200; `completion_tokens` ~ Normal(85, 42) clip 20–340; `prefill_ms` = prompt × laju (A: 0,9 bila cache hit / 6,0 bila miss; B: 5,6 selalu) + noise N(0,45); `queue_ms` ~ Eksponensial(160); `ttft_ms` = prefill + queue; `tpot_ms` = A: N(36, 4) / B: N(21, 2.5) ms per token; `decode_ms` = tpot × completion; `total_ms` = ttft + decode; `quality_score` = A: N(4.35, 0.45) / B: N(3.60, 0.55), clip 1–5, 1 desimal (skor evaluasi sintetis, BUKAN penilaian manusia).
- **Statistik kebenaran (pandas quantile, untuk checks lab):** TTFT A p50=0,61 dtk / p99=4,51 dtk; TTFT B p50=2,83 dtk / p99=5,53 dtk; TPOT A p50=36,17 / p99=45,28 ms per token; TPOT B p50=20,80 / p99=25,70 ms per token; total p99 gabungan 7,72 dtk (≈ keluhan "p99 8 detik" di briefing); hit rate A=0,858 / B=0,000; korelasi cache_hit vs prefill_ms = −0,79; biaya per 1k request (asumsi GPU $3,20/jam) A=$3,48 / B=$4,14 — varian "hemat" justru lebih mahal karena cache mati.
- **Tanggal tangkapan:** 2026-10-15. Ukuran: ±14,7 KB (di bawah batas 5 MB).
- **Batas jujur:** angka-angka ini ilustrasi untuk latihan serving LLM; laju prefill/decode, harga GPU ($3,20/jam), ambang SLO (TTFT p99 ≤ 2 dtk), dan skor kualitas disederhanakan untuk misi ini — bukan benchmark resmi model atau provider mana pun. Rumus biaya memakai waktu GPU per request sebagai proksi; di produksi ada faktor batching, utilitas, dan overhead orkestrasi.
